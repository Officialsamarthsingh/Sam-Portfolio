Customer Churn Prediction — XGBoost + FastAPI + Streamlit

PythonXGBoostScikit-learn SMOTESHAPFastAPI StreamlitPandasSeaborn

S — An e-commerce company needed to identify customers likely to churn from a dataset of 5,630 records (671 duplicates removed), with a 16.3% churn rate too imbalanced for plain accuracy to be meaningful.
T — Build a classifier that correctly flags churn risk using F1 and ROC-AUC as the evaluation metric, then deploy it as a live prediction tool.
A — Applied SMOTE to balance training data, compared 5 classifiers (Logistic Regression, KNN, SVM, Random Forest, XGBoost) on the real imbalanced test set. GridSearchCV tuning was tried but the tuned model overfit to synthetic samples — so the untuned XGBoost baseline was deliberately kept. Used SHAP to explain predictions: Tenure ranked #1, followed by Complain and CashbackAmount. Serialised with joblib and deployed via FastAPI (POST /predict) + Streamlit UI on Render.
R — XGBoost achieved F1 = 0.78 and ROC-AUC = 0.957 on the held-out test set. Live app running at churn-predictor-ui-2ic6.onrender.com.

Key Finding
New customers (low tenure) and complainers are the highest-risk segment. Retention spend is best directed at customers in months 1–6 before loyalty sets in, and complaint resolution speed matters more than cashback incentives — SHAP ranks Complain above CashbackAmount in churn impact.

Laptop Price Prediction (ML Regression)

PythonPandasNumPyScikit-learn Ridge RegressionFeature Engineering MatplotlibSeaborn

S — No clean, consolidated laptop pricing dataset existed — real-world pricing data was spread across four separate Kaggle sources that needed merging into a single 3,918-row master dataset.
T — Build a regression model that predicts laptop price from hardware specs, handling messy categorical features like raw CPU strings with hundreds of unique values.
A — EDA revealed strong right skew (skewness 2.08), so the target was log-transformed. Feature engineering used regex to extract cpu_brand (6 categories), cpu_tier (i3/i5/i7/i9/Ryzen/Apple Silicon), and gpu_type from raw processor strings. Brand was target-encoded to median log-price to avoid 36 sparse dummy columns. Compared Linear Regression, Ridge, and Lasso on an 80/20 split with StandardScaler on numeric features.
R — Ridge Regression won with R² = 0.81 and MAE = ₹23,560. Lasso underfit by over-shrinking real signals; Linear Regression matched Ridge — confirming minimal multicollinearity in the feature set.

Key Finding
CPU tier is the single strongest price driver — Ryzen 9 and i9 carry the largest positive coefficients, while Budget/Workstation chips and MediaTek processors are the strongest negative signals. SSD storage and macOS add meaningful price premiums. A buyer targeting value should prioritise i5/Ryzen 5 + SSD combinations over any other spec trade-off.

E-Commerce Sales Forecasting (ML Regression)

PythonPandasScikit-learn Linear RegressionRidgeLasso Feature EngineeringMatplotlibSeaborn

S — Monthly sales data from 2014–2017 showed high volatility with no obvious linear trend — a plain regression on raw dates would miss the temporal dependencies driving the pattern.
T — Build a time-series-aware regression model by engineering lag and rolling features that capture short- and medium-term momentum, then compare models on a chronological split.
A — Aggregated transaction data to monthly level, then engineered lag features (1, 2, 3 months) and rolling averages (3-month, 6-month) to encode temporal structure. Applied StandardScaler to numeric features. Trained Linear Regression, Ridge, and Lasso on an 80/20 chronological train-test split — preserving time order to prevent data leakage.
R — rolling_6_month_avg showed the strongest correlation with the target (r = 0.78). The model captured the overall sales trend; high-volatility spike months remain the hardest to predict without external signals like promotions or marketing spend.

Recommendation
Stock up before November, December, and Q4, which consistently peak. Impose a hard discount ceiling at 30% — the data shows average profit turns negative beyond that threshold. Supplement the model with marketing spend and promotional data to reduce residual error on extreme-spike months.
